UI

UI の部品は、ふつうの コンポーネントです。ゲームの UI は、エディタで置いて、コードで値を読み書きします。置きかたは、UI Studioを見てください。

UI のコンポーネント

Section titled “UI のコンポーネント”
コンポーネント 役割
Canvas UI を載せる板。画面への合わせかたを決める
RectTransform UI の位置と大きさ。UI の部品は、必ず持つ
Image 画像
Text 文字
Button 押せるボタン
ScrollView スクロールする領域
HorizontalLayoutGroup、VerticalLayoutGroup、GridLayoutGroup 子を、横、縦、格子に、並べる
Slider、Toggle、ProgressBar、Dropdown、InputField 値を持つ部品

UI の部品は、Canvas の子 (または孫) に置きます。

画面の大きさに合わせる (Canvas)

Section titled “画面の大きさに合わせる (Canvas)”

Canvas の設定で、画面の大きさが変わっても、UI が崩れないようにします。

項目 働き
Mode ScreenSpaceOverlay (画面に貼り付く。通常) か WorldSpace (3D の空間に置く)
ScalerMode ConstantPixelSize (ピクセルのまま) か ScaleWithScreenSize (画面に合わせて拡縮。初期値)
ReferenceResolution 基準の解像度 (初期は 1920 x 1080)。この大きさを、基準に、レイアウトを作る
MatchMode 画面の比率が、基準と違うときの、拡縮の決めかた
MatchWidthOrHeight MatchWidthOrHeight のとき、幅と高さの、どちらを重くするか (0 が幅、1 が高さ)
ScaleFactor ConstantPixelSize のときの、倍率
SortingLayer 重なる順
IgnorePostProcess 入れると、UI は、ブルームなどの効果の影響を受けない

MatchMode の選択肢です。

値 意味
MatchWidthOrHeight 幅と高さの比を、MatchWidthOrHeight の値で混ぜる
Expand 基準の大きさが、必ず画面に 収まるようにする
Shrink 基準の大きさが、画面を必ず 覆うようにする

迷ったら

1920 x 1080 で UI を作って、ScaleWithScreenSize のまま、MatchMode を Expand にすると、どの画面の比率でも、UI がはみ出しません。画面の比率を変えて確かめるには、Game ビューの比率の欄を使います。

RectTransform の アンカーと Pivot も、配置を保つために、大切です。四隅に置く UI は、その隅にアンカーを付けます。

ボタンの押下を読む

Section titled “ボタンの押下を読む”

Button の WasClickedThisFrame が、押して、離したフレームだけ、true になります。ゲームパッドやキーボードの、決定の操作でも、true になります。

StartButton のような、自分のコンポーネントを Button と一緒に付けると、「このボタンは、これ」と区別できます。ボタンの役割ごとに、コンポーネントを用意します。

項目 意味
WasClickedThisFrame このフレームに、クリックが確定したか
IsHovered マウスが乗っているか
IsPressed 押している最中か
IsFocused ゲームパッドやキーボードで、選ばれているか
CurrentState Normal、Hovered、Pressed、Disabled のどれか
Interactable 押せるか。false にすると、反応しない (Disabled の色になる)

ノート

ボタンの状態は、PreUpdate のシステムが、毎フレームの初めに、更新します。ふつうのゲームのシステム (Logic) からは、そのフレームの状態が読めます。

文字を書き換える

Section titled “文字を書き換える”

Text の Content に、新しい文字を入れます。

  • Content は、FixedString<512> です。std::string や const char* を、そのまま代入できます。512 文字を超えた分は、切られます。
  • 文字は、日本語も使えます。ただし、使うフォント (FontAsset) に、その文字が含まれている必要があります。
  • 毎フレーム、組み立てるときは、上のように、snprintf で、決まった大きさの配列に書くと、メモリの確保が起きません。

Text には、ほかに、Color、FontSize、HorizontalAlignment、WordWrap などがあります。

画像や色を変える

Section titled “画像や色を変える”

ほかのコンポーネントと、同じです。Image の Color や、FillAmount を、書き換えます。

項目 働き
Color 乗算する色 (RGBA)
Type Simple、Sliced (9-Slice)、Tiled、Filled (ゲージ)
FillAmount Filled のとき、満ちている割合 (0 から 1)
FillMethod Filled のとき、塗りかた (横、縦、円など)

`Image` は、`Span::Image` と書く

Process の引数に Image を書くときは、Span::Image& と、名前空間をつけて書いてください。Image だけだと、DirectXTex の DirectX::Image と、名前がぶつかって、ビルドが通りません。(Text や Button など、ほかの部品は、そのまま書けます。)

Slider、Toggle などの動き

Slider、Toggle、ProgressBar、Dropdown、InputField は、値 (Value、IsOn など) を持つ部品です。いまのエンジンが、標準で操作を処理するのは、Button、ScrollView、レイアウト、ナビゲーションです。値を、ゲームの動きに結びつける処理は、自分のシステムで書きます。

ゲームパッドとキーボードで、操作する

Section titled “ゲームパッドとキーボードで、操作する”

UI は、ゲームパッドとキーボードの、ナビゲーションにも、対応しています。矢印やスティックで、ボタンを選び、決定で押せます。

  • 次に選ぶボタンは、位置から、自動で決まります。
  • 自分で決めたいときは、Button の NavigateUp、NavigateDown、NavigateLeft、NavigateRight に、移動先のエンティティを入れます。
  • 既定のキーに加えて、自分のキーを使いたいときは、UINavigationSettings コンポーネントを足して、CustomInputMap に、Input Map を入れます。そのファイルに、UI_Up、UI_Down、UI_Left、UI_Right、UI_Submit という名前の、アクションを作ります。

キー設定の画面

Section titled “キー設定の画面”

ControlsPanel コンポーネントを、UI のエンティティに付けて、TargetMap に Input Map を入れると、そのキーの一覧と、変更の画面が、自動で作られます。キーの変更は、InputRebinder の仕組みで、Saved/KeyBindings.json に保存されます。
